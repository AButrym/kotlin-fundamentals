Посилання на конструктори та методи

Те, що в модулі «Функції» ми лише згадали: ::Person, Person::greet та obj::method.

1. Нагадування

У модулі «Функції» ми передавали наявну функцію замість лямбди: ::isEven (посилання на функцію). Класи додають ще кілька різновидів посилань. Для прикладів візьмемо:

data class Person(val name: String, val age: Int) {
    fun greet(): String = "Привіт, я $name"
    fun isAdult(): Boolean = age >= 18
}

2. Посилання на конструктор

Конструктор можна передати як функцію, що створює об’єкти. Пишуть :: і ім’я класу — constructor reference:

val make: (String, Int) -> Person = ::Person
val olya = make("Оля", 20)     // те саме, що Person("Оля", 20)

Тип такого посилання: параметри конструктора → клас. Зручно, коли «створити об’єкт» треба передати як дію.

3. Посилання на метод і властивість класу

Запис Person::greet — посилання без конкретного об’єкта. Функція отримає об’єкт як перший аргумент:

fun printAll(items: List<Person>, show: (Person) -> String) {
    for (p in items) println(show(p))
}

val people = listOf(olya, make("Іван", 15), make("Марія", 30))
printAll(people, Person::greet)      // Привіт, я Оля / Привіт, я Іван / …
printAll(people, Person::name)       // властивість теж «функція» (Person) -> String

4. Bound-посилання: об’єкт уже вшито

Якщо ліворуч від :: стоїть конкретний об’єкт, він «прив’язується» до посилання — це bound reference, і воно вже не потребує об’єкта як аргумента:

val hello: () -> String = olya::greet
println(hello())                      // Привіт, я Оля

5. Зведена таблиця

Який функціональний тип має посилання Person::isAdult, якщо метод isAdult(): Boolean не має параметрів?

6. Де це застосовують

Посилання на властивості й методи вигідні там, де лямбда лише «передає далі» своє значення. Із функціями колекцій (модуль «Колекції», map / filter) це читається майже як речення:

println(people.map(Person::name))                              // [Оля, Іван, Марія]
println(people.filter(Person::isAdult).map(Person::name))      // [Оля, Марія]
println(listOf("kotlin", "oop").map(::Tag))                    // [#kotlin, #oop]

Тут Tag(val text: String) — клас з одним параметром, а ::Tag — функція (String) -> Tag. Усі ці виклики можна записати й лямбдою (people.map { it.name }); посилання — лише коротша форма.

У val hello = olya::greet який об’єкт «вшито» у посилання? (ім’я змінної)

7. Практика

Для Person створіть val names = listOf("Оля", "Іван") і перетворіть на список Person з віком 18 — лямбдою names.map { Person(it, 18) }. Потім запишіть те саме для Tag через ::Tag і поясніть, чому для Person не вийде просто ::Person (підказка: кількість параметрів).

data class Person(val name: String, val age: Int) {
    fun greet(): String = "Привіт, я $name"
    fun isAdult(): Boolean = age >= 18
}

class Tag(val text: String) {
    override fun toString(): String = "#$text"
}

fun printAll(items: List<Person>, show: (Person) -> String) {
    for (p in items) println(show(p))
}

fun main() {
    // Посилання на конструктор: тип (String, Int) -> Person
    val make: (String, Int) -> Person = ::Person
    val olya = make("Оля", 20)
    println(olya)                          // Person(name=Оля, age=20)

    val people = listOf(olya, make("Іван", 15), make("Марія", 30))

    // Незв’язане посилання на метод: Person::greet має тип (Person) -> String
    printAll(people, Person::greet)
    // Привіт, я Оля
    // Привіт, я Іван
    // Привіт, я Марія

    // Посилання на властивість теж працює як функція (Person) -> String
    printAll(people, Person::name)         // Оля, Іван, Марія (кожне з нового рядка)

    // Зв’язане (bound) посилання: об’єкт уже «вшитий», тип () -> String
    val hello: () -> String = olya::greet
    println(hello())                       // Привіт, я Оля

    println(people.map(Person::name))      // [Оля, Іван, Марія]
    println(people.filter(Person::isAdult).map(Person::name))   // [Оля, Марія]
    println(listOf("kotlin", "oop").map(::Tag))                 // [#kotlin, #oop]
}

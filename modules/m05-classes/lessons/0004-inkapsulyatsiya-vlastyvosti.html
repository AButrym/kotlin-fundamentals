Інкапсуляція та властивості з логікою

Ховаємо внутрішній стан: private, власні getter/setter, обчислювані властивості.

1. Проблема відкритого стану

Якщо всі властивості відкриті, будь-який код може їх зіпсувати:

class Account(var balance: Int)

val acc = Account(100)
acc.balance = -999999      // нічого не заважає

Ідея інкапсуляції: клас сам відповідає за коректність свого стану й надає для змін лише обережні методи (deposit, withdraw), а «сире» значення ховає.

2. Видимість: public і private

За замовчуванням усе в класі відкрите (public). Модифікатор private робить властивість чи метод доступними лише всередині цього класу. Ви вже бачили його в Matrix: масив data був private, а працювали з матрицею через m[r, c]. Інші рівні видимості (protected, internal) — у модулі 7.

3. Читати можна, змінювати — ні: private set

Часто властивість має бути видимою ззовні для читання, але змінюватися лише методами класу. Для цього сеттер роблять приватним:

class Account(val owner: String, initial: Int) {
    var balance: Int = initial
        private set                 // змінювати можна лише всередині класу

    fun deposit(amount: Int) {
        require(amount > 0) { "Сума має бути додатною" }
        balance += amount
    }

    fun withdraw(amount: Int): Boolean {
        if (amount <= 0 || amount > balance) return false
        balance -= amount
        return true
    }
}

val acc = Account("Оля", 100)
acc.deposit(50)
println(acc.balance)       // 150 — читати можна
// acc.balance = 1_000_000 // помилка: сеттер private
Що буде, якщо викликати acc.withdraw(500) при балансі 150? Що поверне метод? (true/false)

4. Обчислювані властивості

Властивість може не зберігати значення, а обчислювати його при кожному зверненні — для цього після неї пишуть get() (getter):

class Rectangle(val width: Int, val height: Int) {
    val area: Int
        get() = width * height
    val isSquare: Boolean
        get() = width == height
}

val r = Rectangle(3, 4)
println(r.area)        // 12 — без дужок, як звичайна властивість
println(r.isSquare)    // false

Ззовні це виглядає як звичайне читання поля, але значення завжди актуальне й окремого поля в об’єкті немає. Порівняйте з методом fun area(): для величин, що «просто описують стан», властивість-вираз читається природніше.

5. Власний setter і field

Сеттер можна описати самостійно, щоб відхиляти некоректні значення. Усередині нього приховане «поле» властивості доступне як field (писати target = value не можна — це знову викликало б сеттер і зациклило б програму):

class Thermostat {
    var target: Int = 20
        set(value) {
            if (value in 10..30) field = value
        }
}

val t = Thermostat()
t.target = 50
println(t.target)    // 20 — некоректне значення відхилено
t.target = 25
println(t.target)    // 25
Початкове значення властивості записується напряму в поле й обходить власний setter. Тому Thermostat().target стартує з 20 без жодних перевірок. Якщо початкове значення приходить ззовні (з конструктора), перевіряйте його окремо, наприклад у init.
Практичне правило: відкривайте мінімум. Властивість — val, якщо її не треба змінювати; private set — якщо змінює лише сам клас; повний var — лише коли зміни ззовні справді безпечні.

class Account(val owner: String, initial: Int) {
    var balance: Int = initial
        private set                    // читати можна всім, змінювати — лише всередині

    val isEmpty: Boolean
        get() = balance == 0           // обчислювана властивість без власного поля

    fun deposit(amount: Int) {
        require(amount > 0) { "Сума має бути додатною" }
        balance += amount
    }

    fun withdraw(amount: Int): Boolean {
        if (amount <= 0 || amount > balance) return false
        balance -= amount
        return true
    }
}

class Thermostat {
    var target: Int = 20
        set(value) {
            if (value in 10..30) field = value   // field — приховане поле властивості
        }
}

class Rectangle(val width: Int, val height: Int) {
    val area: Int
        get() = width * height
    val isSquare: Boolean
        get() = width == height
}

fun main() {
    val acc = Account("Оля", 100)
    acc.deposit(50)
    println(acc.balance)               // 150
    println(acc.withdraw(500))         // false
    println(acc.withdraw(30))          // true
    println(acc.balance)               // 120
    println(acc.isEmpty)               // false
    // acc.balance = 1_000_000         // розкоментуйте: помилка — сеттер private

    val t = Thermostat()
    t.target = 50
    println(t.target)                  // 20 — значення поза 10..30 відхилено
    t.target = 25
    println(t.target)                  // 25

    val r = Rectangle(3, 4)
    println(r.area)                    // 12
    println(r.isSquare)                // false
}

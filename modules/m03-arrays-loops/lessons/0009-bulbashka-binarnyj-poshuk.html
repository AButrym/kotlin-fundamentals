Сортування бульбашкою та бінарний пошук

Обміни, інваріант діапазону, логарифмічний пошук.

1. Сортування бульбашкою

Сортування бульбашкою: проходимо масивом і міняємо місцями сусідні елементи, що стоять не в порядку. Після першого проходу найбільший елемент «спливає» в кінець, після другого — другий за величиною тощо.

fun bubbleSort(a: IntArray) {
    for (pass in 0 until a.size - 1) {
        var swapped = false
        for (i in 0 until a.size - 1 - pass) {
            if (a[i] > a[i + 1]) {
                val t = a[i]          // обмін через тимчасову змінну
                a[i] = a[i + 1]
                a[i + 1] = t
                swapped = true
            }
        }
        if (!swapped) break           // обмінів не було — масив уже впорядкований
    }
}

Приклад для [5, 2, 4, 1, 3]:

ПрохідМасив після проходу
1[2, 4, 1, 3, 5]
2[2, 1, 3, 4, 5]
3[1, 2, 3, 4, 5]
4обмінів немає → вихід
  • Внутрішній цикл щоразу коротший (- pass): хвіст уже відсортований.
  • Функція змінює той самий масив, що їй передали (пригадайте аліасинг з уроку 2), тому нічого не повертає.
  • Складність O(n²) — для навчання чудово, для великих даних є швидші алгоритми.

2. Бінарний пошук

Якщо масив відсортований, шукати можна швидше: беремо середній елемент і відкидаємо половину, де шуканого точно немає. Бінарний пошук підтримує діапазон lo..hi, у якому ще може бути відповідь.

fun binarySearchIndex(a: IntArray, target: Int): Int {
    var lo = 0
    var hi = a.size - 1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2
        when {
            a[mid] == target -> return mid
            a[mid] < target  -> lo = mid + 1   // шукаємо праворуч
            else             -> hi = mid - 1   // шукаємо ліворуч
        }
    }
    return -1
}

Для [1, 3, 5, 7, 9, 11, 13, 15] і цілі 11: перший mid = 3 (значення 7 < 11) → lo = 4; другий mid = 5 (значення 11) → знайдено, індекс 5, усього 2 кроки.

Формула lo + (hi - lo) / 2 дає той самий результат, що й (lo + hi) / 2, але не переповнює Int для дуже великих масивів. А кожен крок зменшує діапазон удвічі, тож складність — O(log n): приблизно 20 кроків на мільйон елементів.

Приблизно скільки кроків потрібно бінарному пошуку для масиву з 1 000 000 елементів?

Бінарний пошук працює лише на відсортованому масиві. На невпорядкованому він поверне довільний результат без жодної помилки.

3. Практика

Модифікуйте bubbleSort так, щоб сортувати за спаданням. Потім перевірте binarySearchIndex на масиві з одним елементом і на порожньому масиві.

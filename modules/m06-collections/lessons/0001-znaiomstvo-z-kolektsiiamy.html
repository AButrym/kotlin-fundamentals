Kotlin Collections · Урок 1 з 9

Знайомство з колекціями: List, Set, Map

Що ви вже знаєте

Ви вже вмієте писати функції, лямбди, оголошувати змінні (var/val), користуватись типами даних та класами. Колекції — це наступний крок: спосіб працювати не з одним значенням, а з цілою групою значень одразу.

Уявіть, що вам потрібно зберегти імена 30 студентів групи. Створювати 30 окремих змінних (val student1 = "Оля", val student2 = "Максим"...) — це не працює. Потрібна структура, яка тримає багато значень одного типу і дозволяє з ними працювати як з єдиним цілим. Це і є колекція.

Три основні типи колекцій

У стандартній бібліотеці Kotlin є три головні типи колекцій. Кожен вирішує свою задачу:

ТипЩо гарантуєПриклад використання
ListПорядок елементів, дублікати дозволеніСписок товарів у чеку
SetКожен елемент унікальнийСписок email, на які вже надіслано лист
MapПари "ключ → значення", ключі унікальніСловник: логін → пароль
val purchases = listOf("хліб", "молоко", "хліб")       // List: порядок + дублікати ОК
val notifiedEmails = setOf("a@x.com", "b@x.com")        // Set: тільки унікальні
val passwords = mapOf("ann" to "1234", "bob" to "0000") // Map: ключ -> значення

Це схоже на масив (Array), який ви вже могли зустрічати, але колекції в Kotlin набагато зручніші: у них є десятки вбудованих функцій (побачимо у наступних уроках), і вони не завжди мають фіксований розмір.

Read-only проти mutable

У Kotlin майже кожен тип колекції існує у двох варіантах:

  • Read-only (List, Set, Map) — інтерфейс, який дає тільки методи для читання: розмір, доступ до елементів, перевірку наявності.
  • Mutable (MutableList, MutableSet, MutableMap) — усе те саме, плюс методи для зміни: додати, видалити, оновити.
val fixed = listOf(1, 2, 3)          // тільки читання
val changeable = mutableListOf(1, 2, 3)
changeable.add(4)                     // OK
// fixed.add(4)                       // помилка компіляції: немає такого методу
Типова пастка

List не завжди означає "об'єкт, який неможливо змінити". Це означає лише "у мене немає методів для зміни через цю змінну". Хтось інший, тримаючи ту саму колекцію як MutableList, може її змінити — і ваш List побачить ці зміни. До справжньої незмінності (immutability) ми повернемось в уроці 7.

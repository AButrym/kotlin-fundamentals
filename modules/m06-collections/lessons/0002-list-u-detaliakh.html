List у деталях

Що ви вже знаєте

З уроку 1: List — впорядкована колекція з дублікатами, MutableList — те саме, але зі змінами. Зараз розберемо, як цим користуватись у реальному коді.

Створення

val readOnly = listOf("a", "b", "c")        // List<String>
val editable = mutableListOf("a", "b", "c") // MutableList<String>
val empty = mutableListOf<Int>()           // порожній, тип треба вказати явно

val built = buildList {          // зручно, коли список складається за логікою
    add("x")
    if (2 > 1) add("y")
}

buildList — це функція-будівельник: усередині лямбди ви працюєте як зі звичайним MutableList, а назовні отримуєте вже готовий read-only List.

Доступ до елементів

val names = listOf("Оля", "Максим", "Ірина")

names[0]              // "Оля" — доступ за індексом
names.first()          // "Оля"
names.last()           // "Ірина"
names.size              // 3
names.getOrNull(10)     // null, а не помилка
names[10]               // IndexOutOfBoundsException!
Типова пастка

list[index] кидає виняток, якщо індексу не існує. Коли індекс може вийти за межі (наприклад, з користувацьких даних), користуйтесь getOrNull() замість квадратних дужок.

Ітерація

for (name in names) {
    println(name)
}

names.forEachIndexed { index, name ->
    println("$index: $name")
}

Зміна mutable-списку

val cart = mutableListOf("хліб", "молоко")

cart.add("яйця")           // [хліб, молоко, яйця]
cart.remove("молоко")      // [хліб, яйця]
cart.removeAt(0)           // [яйця]
cart.contains("яйця")      // true
cart.indexOf("яйця")       // 0
cart.clear()                // []

Що поверне listOf(10, 20, 30).getOrNull(5)?

Який розмір буде у cart після: val cart = mutableListOf("a"); cart.add("b"); cart.add("a")?

Головне джерело

Kotlin Docs: Constructing collections — усі способи створення колекцій, включно з buildList. Додатково: typealias.com — Collections: Lists and Sets.

Застрягли?

Якщо різниця між add(), remove() та removeAt() плутається — це нормально на цьому етапі. Запитайте викладача/агента з конкретним прикладом коду, який не працює так, як очікували.

Вступ до Sequences

Що ви вже знаєте

Ви вже вмієте будувати ланцюжки з map, filter та інших операцій з уроків 4-6. Цей урок — про те, як ці самі ланцюжки виконуються "під капотом", і коли це має значення.

Проблема: зайві проміжні списки

val result = listOf(1, 2, 3, 4, 5)
    .map { it * 2 }      // крок 1: створює ЦІЛИЙ новий список [2,4,6,8,10]
    .filter { it > 5 }    // крок 2: створює ще один новий список [6,8,10]
    .first()               // крок 3: бере перший елемент

На List кожен виклик map/filter одразу обробляє всю колекцію і створює новий список повністю, перш ніж перейти до наступного кроку. Для 5 елементів це неважливо. Але якщо у вас 5 мільйонів елементів і 5 кроків у ланцюжку — це 5 повних проходів і 4 тимчасові списки, які відразу підуть у смітник.

Sequence: лінива обробка

val result = listOf(1, 2, 3, 4, 5)
    .asSequence()
    .map { it * 2 }
    .filter { it > 5 }
    .first()

Sequence обробляє елементи по одному, через весь ланцюжок, а не крок за кроком по всій колекції. Без проміжних списків. І що ще важливіше — first() тут зупиняє обробку одразу, як знайшовся підходящий елемент, не торкаючись решти.

Intermediate vs terminal операції

  • Intermediate (map, filter, ...) — самі по собі нічого не обчислюють, лише описують "що робити далі". Повертають нову Sequence.
  • Terminal (first(), toList(), sum(), ...) — запускають фактичне обчислення і повертають реальний результат.
Типова пастка

Без terminal-операції наприкінці Sequence нічого не обчислить — ланцюжок просто описаний, але не виконаний. Якщо забули .toList() чи подібне в кінці — код "нічого не робить" без жодної помилки.

Коли це реально потрібно

Для маленьких колекцій (сотні-тисячі елементів) різниця непомітна, а Sequence додає трохи зайвого синтаксису. Sequence варта уваги, коли: колекція велика, у ланцюжку декілька операцій підряд, або ви шукаєте лише один елемент (first/find) і хочете зупинитись, щойно він знайдений.

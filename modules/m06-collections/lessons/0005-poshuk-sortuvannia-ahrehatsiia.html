Kotlin Collections · Урок 5 з 9

Пошук, сортування, агрегація

Що ви вже знаєте

З уроку 4: map і filter перетворюють колекцію в іншу колекцію. Зараз розберемо функції, які впорядковують елементи або "стискають" колекцію в одне число чи одну мапу.

Сортування

data class Student(val name: String, val grade: Int)

val students = listOf(
    Student("Оля", 92),
    Student("Максим", 78),
    Student("Ірина", 92)
)

students.sortedBy { it.grade }            // зростання: Максим, Оля, Ірина
students.sortedByDescending { it.grade }  // спадання: Оля, Ірина, Максим

Обидві функції повертають новий список — оригінальний students не змінюється, навіть якщо він MutableList.

Агрегація: одне число з усієї колекції

val grades = listOf(92, 78, 92, 65)

grades.count { it >= 80 }    // 2
grades.sum()                  // 327
grades.average()              // 81.75
grades.maxOrNull()            // 92
grades.minOrNull()            // 65

students.maxByOrNull { it.grade }  // Student("Оля", 92) — перший з максимальних
Типова пастка

maxOrNull()/minOrNull() повертають null для порожньої колекції — саме тому в назві "OrNull". Старі функції max()/min() без цього суфікса у сучасному Kotlin прибрані з stdlib якраз через те, що кидали незрозумілий виняток на порожній колекції.

groupBy — розкласти по категоріях

val byGrade = students.groupBy { it.grade }
// Map<Int, List<Student>>:
// 92 -> [Student("Оля", 92), Student("Ірина", 92)]
// 78 -> [Student("Максим", 78)]

groupBy завжди повертає Map, де ключ — результат лямбди, а значення — список усіх елементів з таким результатом. Це протилежність до map: map зберігає розмір, groupBy перегруповує.

Що поверне listOf(3, 1, 2).sortedBy { it }?

Якого типу буде результат listOf(1, 2, 3, 4).groupBy { it % 2 }?

Головне джерело

Kotlin Docs: Aggregate operations та Grouping. Приклад groupBy у контексті мап: typealias.com — Collections: Maps.

Застрягли?

Тип результату groupBy (Map<K, List<V>>) плутає багатьох новачків. Якщо компілятор скаржиться на тип після groupBy — покажіть повідомлення про помилку викладачу/агенту.

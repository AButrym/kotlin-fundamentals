Mutable колекції на практиці

Що ви вже знаєте

В уроці 1 ми зʼясували: List — це лише "немає методів для зміни через цю змінну", а не гарантія незмінності обʼєкта в пам'яті. Зараз побачимо, чому це важливо на практиці.

Копіювання проти спільного посилання

val original = mutableListOf(1, 2, 3)
val alias = original          // це НЕ копія! Обидві змінні вказують на той самий обʼєкт
val copy = original.toMutableList()  // це справжня незалежна копія

alias.add(4)
println(original)  // [1, 2, 3, 4] — original теж змінився!
println(copy)        // [1, 2, 3] — copy не торкнулись
Типова пастка

Присвоєння val alias = original не створює нову колекцію — обидві змінні вказують на той самий обʼєкт у пам'яті. Якщо потрібна незалежна копія — явно викликайте toList(), toMutableList(), toSet() чи toMap().

Той самий фокус з List і MutableList

val editable: MutableList<Int> = mutableListOf(1, 2, 3)
val readOnlyView: List<Int> = editable   // "вікно" в той самий обʼєкт, без методів запису

editable.add(4)
println(readOnlyView)  // [1, 2, 3, 4] — readOnlyView теж бачить зміну!

Це і є той нюанс з уроку 1: readOnlyView не має методу add(), але сам обʼєкт позаду нього змінився. List — це обмежений набір прав доступу до обʼєкта, а не гарантія його незмінності.

Builder-функції

val report = buildMap {
    put("total", 600)
    put("count", 3)
}

val ids = buildSet {
    add(1)
    add(2)
    add(1)  // дублікат просто ігнориться
}

Builder-функції (buildList, buildSet, buildMap) — це чистий спосіб зібрати колекцію через мутабельний інтерфейс усередині лямбди, а назовні отримати вже "запечатаний" read-only результат — без ризику випадкового аліасингуззовні.

+= та -= для колекцій

val list = mutableListOf(1, 2)
list += 3          // еквівалент list.add(3): змінює той самий обʼєкт
list -= 1          // еквівалент list.remove(1)

var readOnlyList = listOf(1, 2)
readOnlyList += 3   // тут += створює НОВИЙ список і присвоює його змінній
                     // це можливо лише бо readOnlyList оголошено як var

Що буде у b після: val a = mutableListOf(1); val b = a; a.add(2)?

Як отримати справжню незалежну копію mutableListOf(1, 2, 3)?

Головне джерело

Kotlin Docs: Constructing collections — розділи про копіювання (toList, toMutableList...) та builder-функції.

Застрягли?

Аліасинг ("дві змінні — один обʼєкт") — джерело багатьох важко відловлюваних багів навіть у досвідчених розробників. Якщо бачите, що колекція "змінюється сама" — покажіть весь фрагмент коду викладачу/агенту, а не тільки місце, де побачили баг.

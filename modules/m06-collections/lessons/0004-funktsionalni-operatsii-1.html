Функціональні операції I: map, filter, forEach

Що ви вже знаєте

Лямбди та функції ви вже вміли писати до цього курсу (якщо потрібно нагадати синтаксис — typealias.com — Lambdas and Function References). Тут ми просто передаємо лямбду в готові функції колекцій замість написання циклів вручну.

До цього моменту ви обробляли колекції через for. У Kotlin для типових задач — "перетворити кожен елемент", "залишити тільки потрібні", "зробити щось з кожним" — є готові функції, які читаються майже як звичайне речення.

map — перетворити кожен елемент

val prices = listOf(100, 200, 300)
val withTax = prices.map { it * 1.2 }
// [120.0, 240.0, 360.0]

it — це неявне ім'я єдиного параметра лямбди (те саме it, яке ви вже бачили). map завжди повертає нову колекцію того самого розміру, що й вхідна.

filter / filterNot — залишити підмножину

val numbers = listOf(1, 2, 3, 4, 5, 6)

numbers.filter { it % 2 == 0 }     // [2, 4, 6]
numbers.filterNot { it % 2 == 0 }  // [1, 3, 5]

На відміну від map, результат filter може бути меншим за оригінал — або навіть порожнім.

forEach — виконати дію для кожного елемента

numbers.forEach { println("Число: $it") }

// Еквівалент до:
for (n in numbers) { println("Число: $n") }
Типова пастка

forEach не повертає нову колекцію (повертає Unit). Якщо вам потрібен результат — використовуйте map, а не намагайтесь "зібрати" щось усередині forEach у зовнішню змінну.

Пошук одного елемента

numbers.find { it > 4 }         // 5 (перший, що підходить), або null
numbers.first { it > 4 }         // 5, або виняток якщо нема жодного
numbers.firstOrNull { it > 100 } // null

Що поверне listOf(1, 2, 3).map { it * 2 }?

Що поверне listOf(1, 2, 3).firstOrNull { it > 100 }?

Головне джерело

Kotlin Docs: Filtering collections та Collection transformations — офіційний опис map, filter та подібних функцій.

Застрягли?

Якщо не одразу видно, яку функцію обрати для конкретної задачі — це нормально, їх багато. Опишіть викладачу/агенту, що саме хочете отримати "на виході" з колекції, і разом підберете правильну функцію.

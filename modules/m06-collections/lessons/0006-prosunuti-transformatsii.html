Просунуті трансформації: fold, reduce, flatMap, zip

Що ви вже знаєте

sum() та count() з уроку 5 — це вузькоспеціалізовані випадки більш загальної ідеї: "стиснути колекцію в одне значення". fold і reduce — це та сама ідея, але для будь-якої вашої логіки, не тільки суми.

fold — згорнути колекцію в одне значення

val prices = listOf(100, 200, 300)

val total = prices.fold(0) { acc, price -> acc + price }
// старт з 0, потім: 0+100=100, 100+200=300, 300+300=600
// total = 600

fold приймає початкове значення (0) і функцію "накопичувач + поточний елемент → новий накопичувач". Це те саме, що sum(), але написане вручну — а значить, підходить для будь-якої операції, не тільки додавання.

reduce — те саме, але без початкового значення

val longest = listOf("кіт", "жирафа", "слон")
    .reduce { longest, next -> if (next.length > longest.length) next else longest }
// "жирафа"
Типова пастка

reduce бере перший елемент колекції як стартове значення — тому на порожній колекції він кидає виняток. fold завжди безпечний для порожньої колекції, бо початкове значення ви задаєте самі. Коли не впевнені, що колекція непорожня — обирайте fold.

flatMap — розплощити список списків

val groups = listOf(listOf(1, 2), listOf(3, 4), listOf(5))

groups.map { it }      // [[1, 2], [3, 4], [5]] — список списків
groups.flatMap { it }   // [1, 2, 3, 4, 5] — один плаский список

flatMap — це map, після якого всі отримані списки "склеюються" в один.

zip — з'єднати дві колекції попарно

val names = listOf("Оля", "Максим")
val ages = listOf(20, 22)

names.zip(ages)
// [("Оля", 20), ("Максим", 22)] — список пар Pair

associate / associateBy — список у мапу

val names2 = listOf("Оля", "Максим")

names2.associateWith { it.length }
// {Оля=3, Максим=6} — ключ: елемент, значення: результат лямбди

names2.associateBy { it.first() }
// {О=Оля, М=Максим} — ключ: результат лямбди, значення: елемент

Що станеться при виклику emptyList<Int>().reduce { a, b -> a + b }?

Що поверне listOf(listOf(1), listOf(2, 3)).flatMap { it }?

Застрягли?

fold/reduce — концептуально найважча тема курсу поки. Якщо логіка "накопичувач + елемент → новий накопичувач" не складається в голові — попросіть викладача/агента розписати покроково один приклад на дошці.

Set та Map

Що ви вже знаєте

List ми розібрали детально. Set та Map працюють інакше: Set дбає про унікальність, Map зберігає пари "ключ → значення".

Set: тільки унікальні елементи

val a = setOf(1, 2, 2, 3, 3, 3)
println(a)        // [1, 2, 3] — дублікати відкинуто
println(a.size)     // 3

val mutable = mutableSetOf("x", "y")
mutable.add("x")     // нічого не зміниться, "x" вже є
mutable.add("z")     // тепер {x, y, z}

setOf() в Kotlin за замовчуванням зберігає порядок додавання елементів (це LinkedHashSet під капотом) — тобто Set в Kotlin не "перемішує" елементи, як можна очікувати з математичного визначення множини.

Операції над множинами

val fansOfKotlin = setOf("Оля", "Максим", "Ірина")
val fansOfJava = setOf("Максим", "Петро")

fansOfKotlin union fansOfJava        // {Оля, Максим, Ірина, Петро}
fansOfKotlin intersect fansOfJava    // {Максим} — спільні елементи
fansOfKotlin subtract fansOfJava     // {Оля, Ірина} — тільки в першому

Map: пари ключ-значення

val ages = mapOf("Оля" to 20, "Максим" to 22)

ages["Оля"]             // 20
ages["Хтось"]            // null — ключа немає, і немає помилки
ages.getValue("Оля")     // 20
ages.getValue("Хтось")    // NoSuchElementException!
ages.getOrDefault("Хтось", 0)  // 0
Типова пастка

Доступ через map[key] повертає null, якщо ключа немає — і компілятор змусить вас це врахувати (тип буде V?). getValue() натомість кидає виняток. Обирайте свідомо, залежно від того, чи відсутність ключа — це нормальна ситуація, чи помилка програми.

Зміна mutable-мапи та ітерація

val stock = mutableMapOf("хліб" to 5, "молоко" to 3)

stock["хліб"] = 4          // оновити значення
stock["яйця"] = 10          // додати нову пару
stock.remove("молоко")

for ((product, qty) in stock) {
    println("$product: $qty")
}

Застрягли?

Плутанина між map[key] (null) та getValue() (виняток) — одна з найчастіших помилок новачків. Якщо не впевнені, який варіант обрати у своєму коді — покажіть його викладачу/агенту.
